# CueFlow v0.6.3 Trial UI

本版属于 `trial-operation`，在 v0.6.2 匿名试运营底座上完成简单 UI。设计采用极简科技风：
浅灰页面、白色内容区、深色文字和单一蓝色主操作。用户操作保持单列，运营信息按重要性展开。
本契约包含审计对话的修订意见，实施授权后不再重新设计被冻结的业务边界。

## 目标与底座约束

- 复用原有五个静态资源及同源 CSP，不引入前端框架、字体服务、动画库或运行时依赖。
- 不修改 API、公开数据字段、Cookie、HMAC、鉴权、限流、预算准入、执行栅栏或对象存储策略。
- 保持 Artifact Schema 12.0.0、Registry 15、Trial Schema 1，以及 v0.5.4 Artifact 身份语义。
- 版本统一为 0.6.3。main 不复用试运营版本，0.7.0 为未来主线版本预留。
- 不实现深色主题、在线复核编辑器、前端 retry/resume、真实百分比或 ETA。

依据：`src/cueflow/trial_http.py` 的路由和静态资源白名单、`TrialStore.jobs/requests/public_request`、
`config.py`、`registry.py`、`trial_migrations.py` 和 Artifact golden tests。
后端已有 retry/resume 的 Workspace / Core Run 复用能力；延后的是 UI 入口，不能误写成后端不存在。

## 用户页

顺序为品牌导航、用途说明、上传表单、匿名历史说明、最近任务、帮助。
文件区域支持选择、拖入、替换和移除；超长文件名按原文换行，多文件拖入明确拒绝全部选择。
没有媒体时禁用提交；材料和关键词默认折叠，填写后显示数量。
辅助材料按选择顺序提交，关键词按行作为原始证据提交，不转换为词库。

提交期间锁定输入与重复提交，显示“正在上传并提交”。只有收到包含任务标识和状态的成功响应
才清空表单。网络中断、超时、5xx 或异常成功响应保留输入，提示先刷新任务核对；不自动重发。
长媒体上传不施加短暂的人为超时；关闭/隐藏页面不等于取消远端执行。

`GET /trial/jobs` 当前返回当前 visitor 的全部任务。首批渲染 100 条，再每次展开 100 条，显示
“已显示 N / 共 M 个任务”。刷新保留展开数量，复用已有任务节点与焦点。
这只减少首批 DOM 数量，不声称实现分页或降低 HTTP 载荷。
标题使用任务 ID 后八位；后端未提供原文件名，不能给历史任务伪造文件名。

| 状态 | 展示与操作 |
| --- | --- |
| queued / running | 准备开始 / 处理中；允许不定进度标识，不编造进度和完成时间 |
| succeeded | 已完成；仅 `result_available=true` 时显示下载，否则解释结果暂不可用 |
| failed / interrupted | 执行失败 / 已中断；“重新上传”返回选文件入口，明确创建新任务 |
| cancelled / rejected | 已取消 / 未接受；拒绝原因映射为可理解文案 |
| needs_review | 需要人工复核；“当前 Trial 版暂不支持在线复核”，无等待动画 |
| 未知状态 | 状态待确认，不猜测为成功、失败或正在执行 |

未知时长显示“时长待确认”；短于一分钟按秒显示；未知成本用 `—`，不当作零。
下载沿用现有同源 result 路由与短期签名跳转。Cookie 关联当前浏览器历史，清理 Cookie、
隐私模式或更换浏览器可能无法找回记录。原媒体/工作对象最多保存七天，结果无自动过期规则。

## 轮询与错误

任务与 heartbeat 分别采用 15 秒、60 秒完成后再调度。每条流最多一个进行中的请求和一个计时器。
hidden 清除后续计时，visible 即时更新一次；不补发错过的周期，不叠加定时器。
已经发送的请求可正常结束；轮询暂停不取消上传或后端任务。首次读取任务等待首次 heartbeat，
减少匿名 Cookie 初始化竞争；pagehide 停止，pageshow 恢复。

所有响应先读取文本，再尝试 JSON；失败响应即使来自代理 HTML，也按 HTTP 状态给出中文反馈。
413 提示上传内容超过服务器限制，并说明媒体小于 500 MB；辅助材料也可能触发代理总量限制，
不能断言一定是媒体文件本身超过 500 MB。429 使用可用的具体限额原因，5xx 提示暂时不可用。
列表或运营数据更新失败时保留上次成功内容并注明更新失败，首次失败不显示成“没有任务”。

## 运营页

沿用当前标签页 sessionStorage 中的管理密钥；共享展示脚本在运营页不初始化访客和 heartbeat。
指标只按需刷新。四个主要指标为今日 Cookie UV、运行次数、成功率、已计算成本。
其他区域区分每日预算、活动占用、未知费用事后估算、成本覆盖率、未知请求数和处理耗时。
成功率旁明确样本分母；窗口活跃标作“近 5 分钟活跃浏览器”，不等同自然人在线人数。
`requests(limit=100)` 的上限只对应“最近请求”，明确“一条请求不等于一个任务”。

滚动时服务控制栏固定顶部；窄屏保留状态与暂停/恢复按钮，避免挤入标题。
“暂停新任务”不承诺停止正在执行的任务。暂停、恢复、预算覆盖设置/清除均弹出原生 dialog，
原因必填，提交及后续状态刷新期间防止重复操作。失败保留原因，结果不确定时先刷新核对。
弹窗关闭恢复可见操作焦点；键盘滚动留出固定栏空间。

## 可访问性与部署核对

使用可见焦点、原生 button/input/details/dialog、显式 label、状态文字与图形、适量 aria-live，
不只依赖颜色。请求表格仅在自己的有标签滚动区域横向滚动。
`forced-colors` 分支使用 Canvas/ButtonFace/Highlight 等系统色，保留按钮边框与焦点轮廓。
色彩计算：正文对页面 16.10:1、次级文字 5.16:1、主按钮白字 5.17:1、输入边框对白色 3.11:1。
这些计算不代表完整 WCAG 合规认证；实际测试范围在实施报告中单列。

以下文案来自当前部署默认值。调整配置时必须同步核对 UI，不能只改服务器：

| 限制 | 当前值 |
| --- | --- |
| 媒体体积 | 严格小于 500,000,000 bytes |
| 媒体时长 | 严格小于 60 分钟，服务端最终判定 |
| 辅助材料 | 最多 20 份，合计严格小于 100,000,000 bytes，非空 |
| 关键词 | 最多 100 个 |
| 活跃窗口 | 300 秒，隐藏后不立即从统计窗口消失 |

未来 0.6.4+ 候选只读 `/trial/config`，本版不新增接口。
单个 visitor 达到 1000 个任务或试运营超过 60 天，触发后端分页评估；这是治理阈值，不是性能保证。
