# CueFlow v0.6.3 实施报告

日期：2026-09-13。分支：`trial-operation`。对照提交：`b31bcebcf74d86e30240581dba6e74d0dd993772`。

## 实施结果

完成经审计修订的极简浅色 Trial 工作台与运营控制台，版本统一为 0.6.3。
本轮为本地实现和验证，未提交、推送、打标签或部署，没有调用真实 Provider/TOS。
初次完整验证发现一项可在原始提交独立复现的测试时钟缺陷；后续按审计授权修复测试，
产品 stale 判定与 gate 实现保持不变。当前结果见下方验证表。

- 用户页：选择/拖入单媒体、替换/移除、材料与关键词折叠、文件大小显示、提交锁与错误反馈。
- 任务列表：首批 100 条、继续展开、真实总数、稳定节点与焦点；状态区分、真实时长与 SRT 入口。
- 异常语义：多文件拖入不静默取首个；413/429/5xx 兼容 HTML 响应；提交结果不明时保留输入且不自动重发。
- 轮询：15 秒任务、60 秒 heartbeat，隐藏暂停、可见即刷新、不重叠；运营页不触发访客 heartbeat。
- 运营控制：固定暂停入口、操作原因必填；提交到状态刷新结束保持锁定，成本和未知值独立展示。
- 可访问性：键盘、原生 dialog、可见焦点、状态文字、reduced-motion 和 forced-colors 样式。
- 文档：设计契约、部署限制核对、后续分页/config 候选、main 与 trial 的版本号治理。

## 测试时钟缺陷与修复

`tests/test_trial_execution.py::test_interrupted_gate_prevents_new_registry_invocation` 在第 49 行
期待第二次 invocation 抛出 TrialExecutionStopped，但没有抛出。
该测试先通过 `TrialExecutionGate.before_invocation()` 使用真实 `now_utc()` 更新 last_alive_at，
随后用固定的 `2026-09-13T02:00:00Z` stale 阈值清扫。真实运行时间晚于该阈值时，请求不满足过期条件。
独立导出原始 HEAD 到 `.tmp/v063-baseline-9c0384c3`，确认导入来自该副本后重跑，用例同样失败。

审计确认并授权后，仅在该测试中用 monkeypatch 将 `cueflow.trial_execution.now_utc`
固定到 admission 的 UTC 时间。新增断言检查 last_alive_at、清扫返回的 request_id 与 interrupted
状态，保留第二次 invocation 必须被阻止及计数不增长的原有断言。未改生产时间函数或清扫逻辑。
