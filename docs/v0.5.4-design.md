# CueFlow Core 0.5.4 — Web Integration Readiness

本版把现有转写链整理成同一主机、多进程可托管的 Run 引擎。算法、提示词、模型、
GLM candidate-only 规则、完整 ATA 原始响应和逐句 SRT 规则保持不变。
不包含 HTTP、浏览器转码、用户、支付、分布式调度或全局文件去重。

## 最终冻结的三个边界

1. 媒体仍由 `media.py` 准备为 **16 kHz、mono、s16le PCM WAV**。
   保留 presentation timeline、sample-zero、offset、padding 和连续性检查。
   TOS MediaObject 与 TimelineAudio blob 的 hash、长度、字节完全相同。
   不另造 AAC/MP3 中间身份。裸 PCM 约 32,000 字节/秒，一小时约 115.2 MB。
   既有源文件大小及媒体时长限制不变；本版不宣称支持直接上传 20 GB 视频。
2. Office 损坏、密码保护、转换器不可用、格式不支持、超时、空结果或未通过 PDF
   基本完整性检查，均产生 `reference_unavailable` warning 并排除该项。
   全部 Reference 不可用仍可运行。Media 准备失败阻断。
   SQLite 写入失败、冻结数据损坏和取消不伪装成 Reference warning。
3. `retry_run(run_id)` 优先恢复失败/降级节点，重算依赖它的下游，复用其他成功节点。
   无失败/降级且上一轮成功时，才重跑两路 Correction 及其后半段。

## 身份与执行轮次

一个 Workspace 持有一个 Registry；一个 Registry 可以有多个 Project。
Project 仅组织 Run，不向算法注入配置、参考材料或关键词。
Run 的 project_id 可为空；Run 拥有独立目录、OS 执行锁和 artifact namespace。
不通过最近一次 Run 推测执行身份。

Run 创建时固定媒体身份、原始 Reference 成员/顺序和 Keywords。
更换媒体、参考材料或关键词必须 New Run。跨 Run 不复用 ASR。
同一个原始 Reference 准备失败后可以在新轮次恢复；这是可用集合扩大，不是输入替换。
失败的 Office 原件也必须可恢复，因此保存原件对象，转换成功后另存 PDF。
TXT/MD/CSV/JSON 正文不经过 PDF 转换、词库或摘要处理。

`execution_round` 从 1 开始。`retry_run()` 创建新轮次并直接执行，不要求调用方再 execute。
`retry_invocation()` 不增加轮次；只重发指定失败调用，成功检查点继续复用，之后继续执行
尚未完成的依赖链。它不自动重发其他已经失败的调用。旧轮次 invocation 不可在新轮次重试。
已知远端任务的交付恢复只查询原 task_id；没有回执的交付不明不自动重新提交。

| 上一轮情况 | 新轮次执行 |
|---|---|
| ATA 失败 | 复用 Correction/merge/sealed transcript，恢复 ATA → Export |
| Kimi 失败、Qwen 成功 | 复用 Qwen，恢复 Kimi → merge/review → ATA → Export |
| Reference C 不可用，恢复后成功 | 新有效集合使两路 Correction 及其下游失效 |
| Reference C 仍不可用，其余链成功 | 保留有效集合与成功模型结果，产生新轮次 warning/manifest |
| 整轮无失败、无降级 | 复用 Media/Reference/ASR，重跑两路 Correction 与后半段 |
| ATA 已提交、本地序列化/投影失败 | 恢复本地产物/发布，不为此再次调用已成功 ATA |

共享 checkpoint 使用 round=0：media_probe、timeline_audio、media_object、base_asr、peer_asr、
asr_comparison。后半段使用 `(run_id, execution_round, stage, scope)`。
input_digest 校验保留，复用前必须验证，不能用新轮次掩盖损坏摘要。
未受影响的后半段检查点可从上一轮显式携带；旧轮次记录不删除。

## 存储边界

- TOS：标准 WAV、Reference 原件/可用 PDF、各轮 final.srt 与结果 manifest。
- 本地持久执行区：Registry、probe、TimelineAudio blob、ASR、比较、纠错、merge、review、
  ATA 完整 raw、checkpoint 和投影。
- 临时区：Reference 接收快照、Office 独立转换目录、对象 materialization。

Core 不删除调用方传入的媒体文件；CLI 原文件始终属于调用方。
Web 上传适配器在媒体准备与 TOS 提交成功后可删除它自己拥有的原视频临时文件。
Core 后续依赖标准 WAV 及其 TOS 对象，不依赖原视频。需要执行区恢复时仍须保留本地
Registry/artifacts/blob；本版不承诺仅凭 TOS 在另一台主机恢复完整 DAG。

对象保存 bucket、key、version_id、SHA-256、长度与 MIME；签名 URL 按真实调用重新生成。
TOS PUT 使用唯一 key、禁止覆盖；签名和下载绑定 version_id，下载校验字节/hash。
PDF 与图片直接复用其原件对象；Office PDF 是转换产物。
ProviderUpload/file_id 缓存不在本版对象模型中。

PUT 前写 object_transfers intent，网络操作期间不占写事务。丢失回执后先 HEAD 原 key，
只有确认对象不存在才 PUT。成功后写 receipt，再绑定业务记录，最后删除拥有的本地暂存文件。
`cleanup_orphans()` 只接受明确的、属于该 Run 的 transfer IDs，默认 dry-run；
执行时持 Run 锁，拒绝活动 Run，保护 bound 对象及已被资产/结果引用的对象。没有 bucket-wide sweep。

## 生命周期与取消

统一状态：queued / running / needs_review / succeeded / failed / cancelled / interrupted。
interrupted 表示进程或宿主异常终止后，在持有 Run 执行锁的恢复入口确认的中断状态。
恢复仅处理指定 run_id，同时更新当前轮次和进度事件；不会扫描或修改其他 Run。
结果 error.code 为 interrupted，message 仅供人阅读。resume 可续当前轮次，retry_run 可创建新轮次。
Invocation 的 created → definitely_not_sent、sending → delivery_ambiguous 保持独立语义。
阶段：preparing / asr / correction / review / ata / export。
progress 为 null，不虚构全局百分比。progress_events 有递增 event_id，可按游标读取。

取消请求绑定 run_id + execution_round。控制进程用独立短连接写取消标记，不获取执行锁；
Worker 在阶段边界、调用前及 Provider 长轮询/流返回点检查。
已经完成的调用回执、usage 和 raw 不因取消删除。成功提交与取消的竞争在最终短事务内裁决。
cancelled 不保证远端工作撤销，也不保证没有费用。阻塞网络读仍受原调用 timeout 限制。

每次真实付费尝试独立保留 invocation。已完成但 JSON 无效的返回仍记 usage，允许一次
原语义输入的格式重试并产生第二条记录。未知 usage 保持 null；不虚构费用或把 null 计为 0。
远端 task_id 在提交返回后立即持久化；豆包请求 ID 在提交前就记录，明确拒绝不误判为已受理。

## Python / CLI

```python
from pathlib import Path
from cueflow.api import Workspace

workspace = Workspace(Path("execution"))
project_id = workspace.create_project("Sony A6700")
result = workspace.run(Path("video.mp4"), project_id=project_id,
                       references=[Path("notes.md"), Path("manual.docx")],
                       keywords=["Sony A6700"])
result = workspace.retry_run(result["run_id"])
workspace.close()
```

需要由独立 Worker 调度时，`create_run()` 固定输入并返回 queued contract；
Worker 调用 `execute_run(run_id)`。同步便捷入口 `run()` 完成两步。
`retry_run()` 是完整动作，不启动隐式 daemon，也不留下必须额外执行的半个 retry。
配置可用 ProviderFactories 注入，默认工厂在构建时读取环境快照；不扫描工作目录 .env。

```text
cueflow init WORKSPACE
cueflow project-create WORKSPACE NAME
cueflow run WORKSPACE MEDIA --project PROJECT_ID --reference notes.md --keyword TERM
cueflow run WORKSPACE MEDIA
cueflow status WORKSPACE RUN_ID
cueflow retry-run WORKSPACE RUN_ID
cueflow retry-invocation WORKSPACE INVOCATION_ID
cueflow resume WORKSPACE RUN_ID
cueflow cancel WORKSPACE RUN_ID --round 1
cueflow events WORKSPACE RUN_ID --after 0
```

## 结果发布

对外结果使用 `contract_version: "1.0"`；独立于软件 0.5.4、Registry 15 和 Artifact 12.0.0。
Registry 15 包含 interrupted 状态约束；开发期 Registry 14 打开即拒绝，不提供迁移或自动改写。
outputs.srt 是稳定对象描述或 null；包含 execution_round、warnings、逐次 usage、结构化 error。
成功的空 SRT 合法，存储层不能以空文件为由拒绝它。

```text
WORKSPACE/.cueflow/registry.sqlite3
WORKSPACE/runs/RUN_ID/
  .cueflow/artifacts/sha256/
  .cueflow/blobs/sha256/
  .cueflow/writer.lock
  attempts/1/final.srt
  attempts/1/result.json
  attempts/2/final.srt
  attempts/2/result.json
  result.json                 # 当前轮次投影
```

发布顺序：本地原子 SRT → TOS SRT 与 manifest → Registry 提交成功与对象回执 → 当前投影。
没有声称 SQLite 与两个远端对象构成单个分布式事务；中断后以 Registry/intent 为准恢复。
新轮次失败时当前结果是该轮失败、outputs.srt=null；不会伪装成上一轮成功。
`get_result(run_id, execution_round=...)` 可查询旧轮次结果。
TOS 不可用时仍保留 Registry 和本地结果；远端失败 manifest 不保证当次发布成功。

## 发布门槛

必须重新跑算法回归、strict mypy、ruff、编译、sdist/wheel、独立安装和真实 FFmpeg 冒烟。
必须证明同一 Registry 下两个完整 Run 可跨进程同时执行，以及取消不等待执行锁。
真实千问/Kimi 对 PDF URL 的内容读取能力、豆包 ASR/ATA、真实 TOS 和长媒体 acceptance
仍需真实接口验证；模拟测试不能替代该门槛。尤其 Kimi 的 URL 请求能力不能由 SDK
能构造请求推出已经支持。本版不以 Files API fallback 掩盖该验证缺口。
